# Product claim guardrails (Visualping)

Every product sentence in the white paper must match a row here (cite it as G-#) or a newer authoritative source you checked today. Verified as of November 24, 2026. This includes fixed template text, chips and mockups, not only the sentences you write. Fixed template sentences are mapped to rows in the "Fixed template text" section below.

Owner-confirmed facts (Visualping marketing leadership, Nov 24, 2026) override older help articles and reviewer notes: a workspace can have both Site scan and Domain Monitoring (G-3); the first check can run against a blank diff (G-5); Domain Monitoring rescan frequency is set on request (G-4).

If you cannot reach an authority to recheck a row, log "not rechecked, table date 2026-11-24" in the claims log, keep the badge and public prices off, and leave out any dated status claim that row supports. If /trust cannot be rechecked, stop and report: page 6 needs it.

Before each run, recheck the rows the paper uses against the authority named in the row: What's New and help articles for behaviour and dates, /pricing for plan gating and public prices, /trust for security status. If a product fact-check skill or an internal product reference is available, run it on the final text too; where it and this table disagree, follow the more recent dated source and record the conflict in the claims log. Public marketing copy and product behaviour can differ (for example rescan defaults): describe behaviour from help or product docs, and plan availability from /pricing.

## Always label as illustrative
Every mockup alert, AI summary, page list, timeline and example vendor. Use reserved example domains (vendor.example, competitor.example, supplier.example). Never show a real third party as having leaked or published something.
